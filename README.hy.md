# phoenix

**Թաքցրեք տվյալները PNG պատկերների մեջ։**

Phoenix-ը ստեգանոգրաֆիայի գործիք է՝ ամբողջ էկրանով գրաֆիկական ինտերֆեյսով և տերմինալային ոճով։

Phoenix-ը տվյալները տեղադրում է PNG ֆայլի `IEND` բլոկից հետո։ Պատկերի սկզբնական տվյալները չեն փոփոխվում, այնպես որ պատկերը շարունակում է նորմալ բացվել սովորական դիտիչներում։ Անհրաժեշտության դեպքում թաքցված տվյալները կարող եք նաև գաղտնագրել Fernet բանալիով։

```bash
phoenix          # բացել գրաֆիկական ինտերֆեյսը ամբողջ էկրանով
phoenix --help
phoenix --version
phoenix --check  # համեմատել հրապարակված տարբերակի հետ
```

![Phoenix-ի գրաֆիկական ինտերֆեյսը](https://github.com/AdolfMacro/phoenix/blob/main/screenshots/1.png?raw=true)

## Ինչպե՞ս է աշխատում

PNG ֆայլը բլոկների հաջորդականություն է.

```text
89 50 4E 47 0D 0A 1A 0A   ֆայլի ստորագրություն
IHDR ...                    պատկերի վերնագիր
IDAT ...                    սեղմված պատկերի տվյալներ
IEND AE 42 60 82            PNG ֆայլի ավարտ
<ձեր տվյալները>             տվյալները ավելացվում են այստեղ
```

`phoenix/core.py`-ը հերթով կարդում է PNG-ի բլոկները։ Յուրաքանչյուր բլոկի չորս բայթանոց երկարության դաշտը որոշում է հաջորդ բլոկի դիրքը, և ընթերցումը շարունակվում է մինչև `IEND`-ին հասնելը։ `IEND`-ից հետո գտնվող ամբողջ տվյալը համարվում է թաքցված տվյալ։

Այս մոտեցումը `IEND` բայթային հաջորդականությունը պարզապես փնտրելու փոխարեն երկու կարևոր առավելություն ունի.

* Եթե տվյալների մեջ ինքնին հանդիպում է `IEND` հաջորդականությունը, տվյալները **ամբողջությամբ պահպանվում և կարդացվում են**։
* Կտրված, վնասված կամ PNG ֆայլ չհանդիսացող ֆայլերը մերժվում են հստակ սխալով՝ `IndexError`-ի նման ներքին սխալի փոխարեն։

Եթե արդեն տվյալներ պարունակող պատկերի մեջ նոր տվյալ եք գրում, նոր տվյալը ավելացվում է ֆայլի վերջում։ Կարդալու ժամանակ վերադարձվում է վերջին ավելացված տվյալը։

Չի թույլատրվում գրել այն նույն ֆայլի վրա, որը տվյալ պահին կարդացվում է։

## Տեղադրում

```bash
git clone https://github.com/AdolfMacro/phoenix.git
cd phoenix
bash installer.sh
```

Տեղադրիչը գործարկեք **սովորական օգտագործողի անունից**։ Անհրաժեշտության դեպքում այն ինքնուրույն կպահանջի `sudo` թույլտվություն։

Ծրագիրը տեղադրվում է `/usr/src/phoenix`-ում, իսկ `/usr/local/bin/phoenix`-ում ստեղծվում է գործարկման հրաման։

### Կախվածություններ և PEP 668

Debian-ի, Ubuntu-ի, Fedora-ի և Arch-ի նոր տարբերակներում համակարգային Python-ը կարող է նշված լինել որպես արտաքին միջավայրի կողմից կառավարվող։ Այդ դեպքում `pip install`-ը, նույնիսկ `--user`-ով, կարող է վերադարձնել `externally-managed-environment` սխալ։

Phoenix-ը չի փորձում շրջանցել այս սահմանափակումը։ Տեղադրիչը հերթով փորձում է հետևյալ տարբերակները.

1. **Python միջավայր, որտեղ երկու փաթեթներն արդեն տեղադրված են։** Ոչինչ չի տեղադրվում։
2. **Բաշխման փաթեթներ**, եթե հասանելի է փաթեթների կառավարիչ (`apt-get`, `dnf`, `pacman`, `zypper`)՝ `python3-cryptography` և `python3-pyqt6`։
3. **Առանձին virtual environment**՝ `/usr/src/phoenix/.venv` ուղու տակ։

Տեղադրման եղանակը կարող եք ընտրել նաև ձեռքով.

```bash
PHOENIX_DEPS=venv    bash installer.sh   # միշտ օգտագործել virtual environment
PHOENIX_DEPS=distro  bash installer.sh   # միայն բաշխման փաթեթներ
PHOENIX_DEPS=system  bash installer.sh   # միայն արդեն աշխատող Python միջավայր
PHOENIX_PYTHON=/path/to/python3 bash installer.sh
PHOENIX_PREFIX=~/.local/share/phoenix PHOENIX_BINDIR=~/.local/bin bash installer.sh
```

Տեղադրիչը կարող եք կրկին գործարկել։ Եթե virtual environment-ն արդեն գոյություն ունի, այն նորից չի ստեղծվի։ Գործարկման հրամանը նույնպես միշտ պահում է Python-ի բացարձակ ուղին։

### Հեռացում

```bash
sudo rm -rf /usr/src/phoenix /usr/local/bin/phoenix
sudo rm -rf /usr/src/phoenix/.venv      # եթե ստեղծվել էր virtual environment
```

## Գրաֆիկական ինտերֆեյս

Ծրագիրը բացվում է **ամբողջ էկրանով**։ Ձախ կողմի ընտրացանկից հասանելի են չորս էջեր։

| Ստեղն     | Գործողություն                                   |
| --------- | ----------------------------------------------- |
| `1` … `5` | անցնել էջերի միջև (1–4՝ էջեր, 5՝ ելք)           |
| `F11`     | անցնել ամբողջ էկրանի և սովորական պատուհանի միջև |
| `ESC`     | դուրս գալ ամբողջ էկրանի ռեժիմից                 |
| `CTRL+Q`  | փակել ծրագիրը                                   |

`CTRL+C`-ը նույնպես ծրագիրը փակում է առանց լրացուցիչ սխալների։

### 1 · Թաքցնել

Ընտրեք PNG պատկեր, մուտքագրեք տեքստը կամ բեռնեք այն ֆայլից և ստեղծեք արդյունքի ֆայլը։

**«Գաղտնագրել տվյալները նոր Fernet բանալիով»** տարբերակը միացնելու դեպքում Phoenix-ը ստեղծում է նոր բանալի և այն ցուցադրում է միայն մեկ անգամ։

**Պահեք այդ բանալին։ Առանց դրա տվյալները վերականգնել հնարավոր չէ։**

Արդյունքի ֆայլի համար առաջարկվում է `<name>_phoenix.png` անունը։

### 2 · Հանել

Ընտրեք Phoenix-ի միջոցով ստեղծված պատկերը։

Տեղեկությունների տողը ցույց է տալիս պատկերի չափը, թաքցված տվյալների չափը և դրանց գաղտնագրված լինելու կարգավիճակը։

Եթե տվյալները գաղտնագրված են, միացրեք **«Թաքցված տվյալները գաղտնագրված են»** տարբերակը և մուտքագրեք բանալին։ Վերականգնված տեքստը կարող եք պատճենել կամ պահպանել։

### 3 · Մշակող

Հեղինակի տվյալները, հղումները և Phoenix-ի հիմնական շարժիչի կարճ նկարագրությունը։

### 4 · Թարմացում

Տեղական `VERSION.txt` ֆայլի տարբերակը համեմատում է GitHub-ում հրապարակված տարբերակի հետ և ցույց է տալիս՝ արդյոք ձեր տարբերակը արդիական է։

Թարմացումը տեղադրելու համար տեղադրիչը կրկին գործարկվում է և պահանջում է `sudo`։

Պատուհանի ներքևի վահանակը նույնպես գրանցում է կատարված գործողությունները և դրանց ժամանակը։

## Շարժիչի ուղղակի օգտագործում

`phoenix.core` մոդուլը կախված չէ գրաֆիկական ինտերֆեյսից և, բացի `cryptography`-ից, արտաքին կախվածություններ չունի.

```python
from phoenix import core

key = core.generate_key()                       # 44 URL-safe նիշ
token = core.encrypt_payload("secret", key)     # ստեղծում է Fernet token

core.bind("cover.png", "cover_phoenix.png", token)   # գրված բայթերի քանակը
core.read("cover_phoenix.png")                       # token-ը
core.read("cover_phoenix.png", key)                  # "secret"
```

`read(source, key=None)`-ում `None`-ը և դատարկ բանալին տարբեր նշանակություն ունեն։

`None` նշանակում է, որ տվյալները գաղտնագրված չեն։ Ցանկացած այլ տող, նույնիսկ `""`, օգտագործվում է որպես գաղտնագրման բանալի։

Այս կերպ սխալ բանալին ճիշտ է հայտնաբերվում, և հում տվյալները չեն ցուցադրվում որպես արդյունք։

Սխալները վերադարձվում են `PhoenixError`-ով՝ հասկանալի հաղորդագրությամբ.

```python
>>> core.read("notes.txt")
PhoenixError: This file is not a PNG image. Only PNG files are supported.

>>> core.read("bound.png", "wrong-key")
PhoenixError: Wrong decryption key, or the payload was altered.
```

### API

| Ֆունկցիա                                    | Նպատակ                                                                    |
| ------------------------------------------- | ------------------------------------------------------------------------- |
| `bind(source, destination, payload) -> int` | տվյալները գրում է պատկերի պատճենի մեջ և վերադարձնում գրված բայթերի քանակը |
| `read(source, key=None) -> str`             | կարդում է տվյալները և անհրաժեշտության դեպքում վերծանում դրանք             |
| `inspect(source) -> dict`                   | վերադարձնում է պատկերի չափը, տվյալների չափը և գաղտնագրման կարգավիճակը     |
| `is_png(path) -> bool`                      | ստուգում է PNG-ի կառուցվածքը                                              |
| `validate_png(path) -> Path`                | ստուգում է PNG-ի կառուցվածքը և սխալի դեպքում առաջացնում `PhoenixError`    |
| `generate_key() -> str`                     | ստեղծում է նոր Fernet բանալի                                              |
| `encrypt_payload(plaintext, key) -> str`    | տեքստը վերածում է Fernet token-ի                                          |
| `decrypt_payload(token, key) -> str`        | վերծանում է Fernet token-ը                                                |
| `find_payload(blob) -> bytes`               | տվյալները հանում է ֆայլի հում բայթերից                                    |

Անվտանգության սահմանափակումների համար `MAX_IMAGE_BYTES`-ը սահմանված է 256 ՄԲ, իսկ `MAX_PAYLOAD_BYTES`-ը՝ 64 ՄԲ։ Ավելի մեծ մուտքերը մերժվում են՝ դրանք անմիջապես հիշողության մեջ բեռնելու փոխարեն։

## Անվտանգության նկատառումներ

Օգտագործելուց առաջ հաշվի առեք հետևյալը.

* **Տվյալներն ամբողջությամբ անտեսանելի չեն։** Քանի որ դրանք գտնվում են `IEND`-ից հետո, `strings`-ը, hex editor-ը կամ նմանատիպ ցանկացած գործիք կարող է գտնել դրանք։ Ստեգանոգրաֆիան տվյալները թաքցնում է սովորական դիտումից, ոչ թե տեխնիկական վերլուծությունից։
* **Եթե տվյալները կարևոր են, օգտագործեք գաղտնագրում։** Phoenix-ը դրա համար օգտագործում է Fernet՝ AES-128-CBC և HMAC-SHA256։ Բանալիները 32 բայթ են, իսկ սխալ բանալին կամ փոփոխված տվյալները մերժվում են։
* **Բանալու կորուստը նշանակում է տվյալների կորուստ։** Բանալու վերականգնման կամ պահուստավորման մեխանիզմ չկա։ Յուրաքանչյուր գաղտնագրման ժամանակ ստեղծվում է նոր բանալի, որը ցուցադրվում է միայն մեկ անգամ։
* **Բանալին ոչ մի տեղ չի պահվում։** Այն չի գրվում ոչ պատկերի, ոչ էլ `VERSION.txt` ֆայլի մեջ։ Գրաֆիկական ինտերֆեյսը այն պահում է միայն ժամանակավորապես հիշողության մեջ։
* **Բանալին պահեք անվտանգ տեղում։** Այն վերաբերվում է գաղտնաբառի նման։
* Պատկերները բացվում են Qt-ի ֆայլերի ընտրության պատուհանի միջոցով։ Phoenix-ը որևէ ֆայլ կամ տվյալ արտաքին ծառայություն չի ուղարկում։

## Նախագծի կառուցվածքը

```text
phoenix/
├── main.py              մուտքի կետ․ կարդում է արգումենտները և գործարկում ինտերֆեյսը
├── phoenix/
│   ├── core.py          ստեգանոգրաֆիայի շարժիչը՝ առանց գրաֆիկական կախվածությունների
│   ├── gui.py           պատուհանը, էջերը և ֆոնային աշխատանքները
│   ├── widgets.py       վերնագիր, կոճակներ, Matrix rain և scanline էֆեկտներ
│   └── updates.py       տարբերակի ստուգում և թարմացման գործիքներ
├── tools/
│   ├── updater.py       հին մուտքի կետը՝ աշխատանքը փոխանցում է updates մոդուլին
│   └── updater.sh       ստանում է նոր տարբերակը և կրկին գործարկում տեղադրիչը
├── installer.sh         PEP 668-ի հետ համատեղելի տեղադրիչ
├── VERSION.txt          տարբերակի հիմնական աղբյուրը
└── screenshots/1.png
```

## Տարբերակավորում

Տարբերակը պահվում է `VERSION.txt`-ում և հանդիսանում է փաթեթի տարբերակի, պատուհանի վերնագրի և `phoenix --version` հրամանի հիմնական աղբյուրը։

Տարբերակները համեմատվում են ըստ թվային արժեքների, ոչ թե որպես տողեր։ Օրինակ՝ `0.10`-ը ճիշտ կերպով համարվում է `0.9`-ից բարձր։

Հրապարակված տարբերակը կարդացվում է հետևյալ հասցեից.

```text
https://raw.githubusercontent.com/AdolfMacro/phoenix/main/VERSION.txt
```

Տարբերակը փոխելիս թարմացրեք `VERSION.txt`-ը, `phoenix.VERSION`-ը և `main.py`-ում պահվող տարբերակի արժեքը։

## Գործարկում կլոնավորված նախագծից

```bash
python3 main.py           # գրաֆիկական ինտերֆեյս
python3 main.py --version
python3 main.py --check
```

Ուղղակի գործարկման համար `cryptography` և `PyQt6` փաթեթները պետք է տեղադրված լինեն այն Python միջավայրում, որով աշխատեցնում եք ծրագիրը։

Եթե PyQt6-ը տեղադրված չէ, `main.py`-ը սովորական `ImportError` ցույց տալու փոխարեն կտպի անհրաժեշտ տեղադրման հրամանը։

## Արտադրողականություն

Գրաֆիկական ինտերֆեյսի ամենածանր մասը ամբողջ էկրանի ֆոնային անիմացիան է։

Ծախսը ցածր պահելու համար.

* Փայլող վերնագիրը pixmap-ի վրա ստեղծվում է միայն **մեկ անգամ**, իսկ հետո կրկին օգտագործվում է։
* Scanline-ները պահվում են առանձին շերտում և ցուցադրվում մեկ գործողությամբ։
* Կոճակները նախապես պահում են իրենց տարբեր վիճակների պատկերները (Hover, սեղմված, անջատված, Focus)։
* Matrix rain-ը նկարվում է առավելագույնը 1600×900 չափով buffer-ում և հետո մեծացվում է։ Այդ պատճառով դրա ծախսը չի աճում էկրանի չափի հետ։
* Կադրերի արագությունը կարգավորվում է ավտոմատ։ Եթե մեկ կադրի մշակումը տևում է ավելի քան 9 միլիվայրկյան, անիմացիան դանդաղում է։

2304×1296 չափով, անգործության մեջ գտնվող ամբողջ էկրանով պատուհանի չափումները ցույց են տվել, որ ամբողջական վերանկարումը տևում է մոտ 14 միլիվայրկյան, իսկ անիմացիայի ժամանակ ծրագիրը օգտագործում է պրոցեսորի մոտ մեկ երրորդ միջուկը։
